PROJECT 02 / ENGINEERING WALKTHROUGH

Agentic product and order search

A multi-step search workflow connecting natural-language questions with business data and tools.

01 / What problem does it solve?

Some business questions require several related retrieval steps. A single response from a language model is insufficient when the answer depends on product or order records. The workflow connects conversational reasoning with access to business data.

This page separates the project experience from illustrative examples and review criteria. Examples explain the architecture; they are not production screenshots or measured outcomes.

02 / How the system works, step by step

Follow the request through the system. Each stage has a different responsibility; the output of one stage becomes useful input for the next.

STEP 01

Receive the request

The backend accepts a natural-language question about products, orders or related business information.

STEP 02

Orchestrate the workflow

ADK and LangGraph provide workflow orchestration for handling the request across multiple steps.

STEP 03

Retrieve business data

BigQuery-backed retrieval provides business records relevant to the query. Tool integrations connect the workflow to external systems through MCP.

STEP 04

Carry context between steps

Pass relevant results forward so later operations can use earlier findings rather than treating every step as an isolated question.

STEP 05

Compose the response

Combine retrieved information with the conversational response workflow using Claude.

STEP 06

Observe execution

Backend APIs, application logs and monitoring help investigate data retrieval, workflow behavior and performance issues.

05 / An example user journey

Illustrative scenario: a user asks for information that depends on both a product record and an order record. The workflow retrieves the relevant business data, carries useful context between steps and prepares a response. No real customer records or database schemas are shown.

06 / Design decisions and tradeoffs

  1. Multi-step workflows can resolve richer requests, but each extra operation adds latency and another possible failure point.
  2. Intermediate context must preserve useful identifiers and findings without carrying unnecessary data into every step.
  3. When a direct lookup is sufficient, a complex agent workflow may add unnecessary overhead. Workflow complexity should follow the information needed.

07 / What to check before relying on the system

  1. Check whether the workflow selects the relevant data source and returns records that answer the request.
  2. Inspect how missing records and failed tool operations are surfaced to the user.
  3. Review logs to distinguish retrieval delays from model or orchestration delays.

08 / Technical terms in plain English

Agent workflow
A sequence of reasoning, retrieval and tool steps used to resolve a request.
ADK
Agent Development Kit: tooling for building and coordinating agent workflows.
MCP
Model Context Protocol: a standard interface for connecting applications to tools and data.
BigQuery
A cloud data warehouse used here for business data retrieval.
Orchestration
Coordinating the order of steps and passing information between them.
