01 / 03 LOCAL DEVELOPER TOOL

CodeAtlas.
MCP

Give coding agents structural context—not an entire file dump.

Indexes Python source into an AST/SQLite snapshot and exposes five MCP tools for symbol lookup, static call candidates and potentially impacted tests.

In simple words: A map of Python code that helps a coding assistant find functions and their possible connections.

Read Python→Build a map→Answer MCP queries
PythonASTSQLiteMCP
How it works ↗Try graph demo ↗ Code + tests ↗
What's implemented, and what's not

Locally runnable MCP stdio service; static Python candidate relationships rather than complete type-aware call resolution. The browser visualizer is a sample graph. Token-count comparisons are not end-to-end coding-agent savings.

02 / 03 HOSTED PYTHON API

Agent.
Gate

Put policy between an agent and its tools.

A hosted FastAPI prototype for tool allowlists, argument validation, selected sensitive-data redaction, session limits and one-use request-bound approvals.

In simple words: A security checkpoint that decides whether an agent's tool request is permitted before a simulated tool runs.

Request→Policy checks→Demo result
FastAPIPolicyRedactionDocker
How it works ↗Try live policy checks ↗ Live API docs ↗ Source ↗
What's implemented, and what's not

Public FastAPI documentation and protected API endpoints are hosted on Railway. The sample tool adapters return simulated results; no real notifications are sent. This is not a complete prompt-injection firewall or generic MCP proxy.

03 / 03 HOSTED PYTHON API

Route.
Wise

Send each request down an explainable path.

A hosted FastAPI gateway with deterministic fast/reasoning selection, bounded provider retries, authenticated metrics and labeled no-provider demo responses.

In simple words: A traffic director that chooses a fast or reasoning route and may try a backup for certain errors.

Incoming prompt→Choose route→Possible fallback
FastAPIHTTPXRoutingFailover
How it works ↗Try live routing ↗ Live API docs ↗ Source ↗
What's implemented, and what's not

Route selection is based on deterministic heuristics, not trained semantic routing. The public route-inspection endpoint computes real server-side decisions; generating LLM answers still requires configured upstream providers.
