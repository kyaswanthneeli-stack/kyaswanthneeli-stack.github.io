RouteWise.

A traffic director for requests to language models. RouteWise is a hosted FastAPI gateway that chooses a fast or reasoning route using simple rules, optionally calls a configured model provider, and tries an alternate provider for eligible retryable failures.

01 / START HERE

What is it, really?

Applications may want predictable routing behavior and a bounded fallback instead of tying every request to one upstream provider. RouteWise demonstrates that gateway logic transparently.

IN EVERYDAY LANGUAGE

Imagine a receptionist directing ordinary questions to the quick-service desk and harder questions to the specialist. If the chosen desk is temporarily unavailable, a second desk may be tried. That is the routing pattern—without claiming the rules always pick the best model.

05 / OPEN THE EVIDENCE

Show the working parts.

✓ Implemented

  • Fast/reasoning selection uses explicit deterministic rules and optional overrides.
  • Bearer authentication protects chat and metrics endpoints.
  • Configured HTTPS providers can be called with at most two sequential attempts.
  • Retry is limited to eligible transient errors.
  • Unconfigured mode clearly labels fixture responses as demos.

○ Not claimed

  • No actual LLM is connected to the public Railway deployment.
  • The classifier is keyword/length based, not semantic or learned routing.
  • No streaming, tool calling, caching or circuit breaker.
  • Stored metrics are memory-only, limited to successes and reset on restart.
  • No proven quality, latency or cost improvement compared with a baseline.

06 / QUESTIONS THAT MATTER

Understand the trade-offs.

COMMON QUESTION

Does the public API call GPT or Claude?

No. In its current configuration it returns a response explicitly saying no language model was called.

COMMON QUESTION

How does it decide between fast and reasoning?

It uses deterministic rules: text length, listed keywords or the client's explicit override.

COMMON QUESTION

Will it always retry failures?

No. It only retries eligible transient errors and requires a configured alternate provider.

Being clear about limitations is part of engineering: the project shows patterns and testable code, not a promise of production security, measured cost reduction or unconfigured model inference.

07 / KEY WORDS

No jargon left behind.

Gateway
A service that receives a request and forwards it according to rules.
Heuristic
A transparent rule of thumb rather than a trained model.
Fallback
Trying an alternate provider after certain transient failures.
Latency
Elapsed time taken to process a request.
